# EstateIQ Multi-Utility Resource Simulator Documentation

> **DISCLOSURE & PROVENANCE NOTICE**
> 
> **ALL READINGS GENERATED BY THIS SIMULATOR ARE SYNTHETIC DEMONSTRATION DATA.**
> All emitted telemetry carries `source_type: "simulated_iot"` and `is_verified_hardware: False`, tagged with `[SIMULATED IoT]`. Simulated data must never be presented as certified hardware readings or used for utility billing reconciliation.

---

## 1. Overview & Architecture

The **EstateIQ Multi-Utility Resource Simulator** is a dedicated demo data generation suite designed for live presentations, pipeline stress testing, and scenario evaluations across four major campus resources:
1. **Electricity** (Active Power, Cumulative Energy, Single-Phase Voltage, Current, Power Factor, Frequency)
2. **Water** (Volumetric Flow Rate, Cumulative Volume, Hydrostatic Pressure)
3. **Air Quality** (Carbon Dioxide concentration, PM2.5, PM10, Temperature, Humidity, EPA AQI)
4. **Waste Management** (Dumpster Volumetric Fill %, Derived Mass kg, Overflow Risk, Collection Status)

### Key Architectural Tenets
- **Non-Disruptive & Isolated**: Runs completely independently of the existing physical gateways, the IoT monitor, and the standalone simulator on port 8502.
- **Physics-Grounded Mathematical Formulations**: Variable interactions follow real-world physical and engineering principles (e.g., Ohm's/power law $P = V \times I \times \text{PF} / 1000$; hydraulic pressure drop under high flow; human respiration scaling of indoor $\text{CO}_2$; monotonic energy and volume totalizers).
- **Dual-UI Availability**: Fully integrated into both the **FastAPI Web App** (`http://localhost:8000/#resource-simulator`) and the **Streamlit Command Center** (`app.py`).
- **Automated Ingestion**: Seamlessly streams packets to `/api/v1/iot/telemetry` and registers virtual devices within `GLOBAL_DEVICE_REGISTRY`.

## 2. Accessing & Running the Simulator

### Option A: Modern Web Application (FastAPI + Vanilla JS / Chart.js)
1. Launch the API backend:
   ```cmd
   run_api.bat
   ```
2. Navigate to `http://localhost:8000` in your web browser.
3. In the sidebar or top tab bar, click on **Resource Simulator** (or navigate directly to `#resource-simulator`).
4. **Controls Available**:
   - **Start All / Pause All / Stop All**: Global orchestration of all 4 streams.
   - **Sample Interval Dropdown**: `1.0s (High-Speed Demo)`, `2.0s (Fast)`, `5.0s (Default Live)`, `10.0s (Eco Mode)`.
   - **Sub-Tabs**: Switch between `All 4 Utilities (Grid View)` or zoom into any single utility.
   - **Per-Resource Controls**: Sliders, scenario dropdowns, pause toggles, and totalizer reset buttons.
   - **Live Charts**: Real-time 25-point ring-buffer time-series powered by Chart.js.

### Option B: Streamlit Command Center
1. Launch the Streamlit command center:
   ```cmd
   run_dashboard.bat
   ```
2. In the sidebar navigation radio, select **`Resource Simulator (IoT)`**.
3. Use interactive sliders, scenario presets, and the **Step +1** or **Start All** actions to generate readings and inspect live Plotly charts.

## 3. Utility Subsystems & Physics Formulations

### 3.1 Electricity Meter (`SIM-ELEC-01`)
- **Associated Facility / Building**: `FAC_GEC_CAMPUS` / `Block B Hostel`
- **Adjustable Controls**:
  - Baseline Active Power: 10 kW to 250 kW (Default: 55 kW).
  - Scenarios:
    - `Normal Operation`: Diurnal baseline with small Gaussian noise ($\pm 2.5\%$). Nominal 230V, PF 0.95, 50.0 Hz.
    - `Peak Demand Surge`: Chiller startup / simultaneous HVAC spike ($1.85\times$ baseline). Slight voltage sag (224V), PF drops to 0.91.
    - `After-Hours Waste`: Unoccupied abnormal load ($1.35\times$ baseline) caused by lighting/HVAC left on overnight.
    - `Voltage Instability`: Severe voltage swings ($205\text{V} - 255\text{V}$), degraded power factor (0.76), fluctuating frequency ($49.2\text{ Hz} - 50.8\text{ Hz}$).
- **Physical Relationships**:
  - Current computation:
    $$I = \frac{1000 \times P_{\text{kW}}}{V \times \text{PF}} \quad [\text{Amperes}]$$
  - Monotonic Cumulative Energy:
    $$\Delta \text{kWh} = P_{\text{kW}} \times \frac{\Delta t_{\text{sec}}}{3600}$$
    $$\text{kWh}_{t} = \text{kWh}_{t-1} + \Delta \text{kWh}$$

### 3.2 Water Flow Meter (`SIM-WATER-01`)
- **Associated Facility / Building**: `FAC_GEC_CAMPUS` / `Block B Hostel`
- **Adjustable Controls**:
  - Baseline Flow Rate: 5 L/min to 150 L/min (Default: 35 L/min).
  - Scenarios:
    - `Normal Operation`: Intermittent campus fixtures and cooling tower makeup ($1.0\times \pm 8\%$). Pressure: 3.4 bar.
    - `Sustained Pipe Leak`: Unbroken continuous leak floor ($+26.5\text{ L/min}$ continuous 24/7). Pressure: 2.8 bar.
    - `Burst / Major Rupture`: Catastrophic pipe fracture ($4.2\times$ baseline surge). Hydrostatic pressure collapses to 1.4 bar.
    - `Low / No Flow`: Night shutdown or supply cutoff ($< 1.5\text{ L/min}$). Static pressure: 1.8 bar.
- **Physical Relationships**:
  - Monotonic Cumulative Volume:
    $$\Delta m^3 = \frac{\text{Flow (L/min)} \times (\Delta t_{\text{sec}} / 60)}{1000}$$
    $$m^3_{t} = m^3_{t-1} + \Delta m^3$$

### 3.3 Indoor Air Quality Station (`SIM-AIR-01`)
- **Associated Facility / Building**: `FAC_GEC_CAMPUS` / `Block B Hostel`
- **Adjustable Controls**:
  - Baseline Building Occupants: 0 to 400 people (Default: 120 people).
  - Scenarios:
    - `Normal Indoor`: Well-ventilated baseline ($\text{CO}_2 \approx 410 + 1.8 \times \text{Occ} \approx 625\text{ ppm}$, $\text{PM}_{2.5} \approx 16\text{ }\mu\text{g/m}^3$, $\text{PM}_{10} \approx 27\text{ }\mu\text{g/m}^3$, AQI Good).
    - `Poor Ventilation`: Fresh air makeup damper restricted. $\text{CO}_2$ accumulates rapidly ($1450 + 3.2 \times \text{Occ} \approx 1800 - 2700\text{ ppm}$), RH rises to 68%, AQI Moderate/Sensitive.
    - `Particulate Spike`: Outdoor wildfire/dust intrusion. $\text{PM}_{2.5}$ jumps to $125\text{ }\mu\text{g/m}^3$, $\text{PM}_{10}$ jumps to $205\text{ }\mu\text{g/m}^3$, AQI Unhealthy ($170 - 230$).
    - `Sensor Fault / Drift`: Erratic thermal and particulate fluctuations ($28^\circ\text{C} - 35^\circ\text{C}$ drift).
- **Physical Relationships**:
  - $\text{CO}_2$ scales with human respiration and ventilation air exchange rates.
  - $\text{PM}_{10} \approx 1.6 \times \text{PM}_{2.5}$.
  - EPA AQI computed using standard piecewise linear interpolation against official breakpoint brackets.

### 3.4 Smart Dumpster Bin (`SIM-WASTE-01`)
- **Associated Facility / Building**: `FAC_GEC_CAMPUS` / `Block B Hostel`
- **Adjustable Controls**:
  - Accumulation Rate: 0.5% to 15.0% per step (Default: 2.5% per step).
  - Scenarios:
    - `Normal Weekday Accumulation`: Steady linear fill progression.
    - `Campus Event / Rapid Fill`: Large event / banquet disposal ($+14.0\%$ per step).
    - `Bin Full / Overflow Risk`: Pinned at $92\% - 98\%$. Overflow risk Critical, pickup overdue.
    - `Emptied / Post-Collection Reset`: Collection truck empties the bin; fill level drops back to $4.0\% \pm 0.5\%$, mass resets to $\sim 6\text{ kg}$.
- **Physical Relationships**:
  - Standard 1100-Liter commercial waste container.
  - Average uncompacted municipal solid waste density $\approx 0.15\text{ kg/L}$ (Full capacity $\approx 165\text{ kg}$).
  - Estimated Mass:
    $$\text{Mass (kg)} = \left(\frac{\text{Fill \%}}{100}\right) \times 1100 \times 0.15 \times \text{stochastic factor}$$
  - Overflow Risk Tiers: $<50\%$ Low, $50-75\%$ Medium, $75-90\%$ High, $\ge 90\%$ Critical.

## 4. Telemetry Schema & Ingestion Contract

All telemetry packets posted to `POST /api/v1/iot/telemetry` follow the canonical EstateIQ schema:

```json
{
  "message_id": "MSG_SIM_ELEC_1794039211809_412",
  "simulator_id": "SIM_RESOURCE_DEMO_01",
  "device_id": "SIM-ELEC-01",
  "device_name": "Block B Main Power Submeter",
  "facility_id": "FAC_GEC_CAMPUS",
  "building_id": "Block B Hostel",
  "source_type": "simulated_iot",
  "is_verified_hardware": false,
  "data_source_badge": "[SIMULATED IoT]",
  "event_timestamp": "2026-11-07T08:15:10Z",
  "measurements": {
    "active_power_kw": 55.4,
    "cumulative_energy_kwh": 3422.1,
    "voltage_v": 230.1,
    "current_a": 252.0,
    "power_factor": 0.95,
    "frequency_hz": 50.02
  }
}
```

### Safety Guarantees:
1. `source_type == "simulated_iot"` prevents any downstream billing module from misinterpreting test readings as certified utility bills.
2. `is_verified_hardware == False` blocks hardware trust elevation.
3. Bounded history caches and idempotent message ID deduplication prevent memory growth or duplicated writes.

## 5. Verification & Automated Test Suite

A dedicated pytest test suite is located in `tests/test_resource_simulator.py`.

To run the verification suite:
```cmd
pytest tests/test_resource_simulator.py -v
```

### Test Coverage Summary:
- `test_electricity_physics_and_plausibility`: Verifies $P = V \cdot I \cdot \text{PF} / 1000$ and monotonic energy progression.
- `test_water_flow_and_monotonic_volume`: Checks hydraulic pressure correlation and monotonic cubic meter totalizer.
- `test_air_quality_metrics_and_epa_aqi`: Validates indoor $\text{CO}_2$ respiration scaling and EPA AQI piecewise calculation.
- `test_waste_accumulation_and_reset`: Checks bin volume-to-mass derivation, risk categorization, and truck reset behavior.
- `test_telemetry_provenance_and_hardware_flags`: Ensures provenance tags (`simulated_iot`, `is_verified_hardware=False`, `[SIMULATED IoT]`) are strictly enforced.
- `test_registry_telemetry_ingestion_end_to_end`: Tests multi-stream ingestion directly into `GLOBAL_DEVICE_REGISTRY`.
- `test_all_utility_scenarios_bounds`: Checks boundary safety across all 16 scenario permutations.
- `test_monotonic_counter_integrity_and_idempotency`: Verifies duplicate packet rejection and forward monotonic auditing.

## 6. Limitations & Boundaries
- All models operate on deterministic differential equations with Gaussian perturbation; they do not simulate thermodynamic building envelope heat transfer.
- Simulated readings remain isolated to demo devices (`SIM-ELEC-01`, `SIM-WATER-01`, `SIM-AIR-01`, `SIM-WASTE-01`) within `Block B Hostel`.
- If the backend REST API is stopped, the Web UI automatically falls back to local client-side simulation while clearly displaying `LOCAL SIMULATION (API OFFLINE / STANDALONE)`.
